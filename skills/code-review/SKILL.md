# code-review — 本仓评审规程

## 适用场景
- 有人给你一个 PR/sha 让你评审
- 你要自查"这单能不能合"

## 铁律
1. **只读**：不改仓库、不 `git add/commit/switch/checkout`、不动设备。产物只写 `/tmp/outbox/<角色>-<任务>.md`。
2. **不看结论看证据**：每条判定要么引 `git`/`grep`/`wc` 的真实输出，要么标 `TODO(未核)`。
3. **不自评不自批**：作者写的自测值不算依据；作者给的"重点看哪里"不算依据。
4. **改结论要全文搜同义断言**：`91%`、`ORT 推理`、`跨语言编组` 这类词常散在标题/表头/正文三四处，只改一处必留矛盾（本仓真实翻车 3 次）。
5. **百分比/中位数必须同源**：表头写"中位数"，分母就得是中位数，不能用均值凑。

## 必查（WORKFLOW §5 八条）
1. 范围：`git diff <锚点>..HEAD --stat` 与派单范围一致，无夹带
2. 硬约束：分辨率/dpi、开机自启、版本矩阵、`server.jar` 字节、构建方式（AGENTS §2）
3. 事实性：每条可验证声明（字节/行数/条数/路径/类名/命令）都能现查证实
4. 证据链：引用的 evidence/日志存在且支撑结论；标"原文"的引文逐字
5. 规则自洽：规则文件内部与跨文件不矛盾；失效条款已清
6. 上限与门禁：AGENTS ≤50 行/5,120 B、PROGRESS ≤40 行/4,096 B、DECISIONS 新增 ≤300 B；`gate.sh --static` PASS
7. 越线：没碰不该碰的；PROGRESS 没写死 PR 号/sha；只读位没动仓库
8. 复活检查：没把已删/已废弃之物当现存（文件、包、分支、岗位）

## 进阶（本仓专属检查）
- **注释与代码是否同步**：`marshal` 段曾只包 `tolist()` 却注释成"跨语言编组"，直接导致错误结论。
- **"界内/界外"**：跨语言调用（Python↔Kotlin）里，编组发生在哪一侧要按代码读，不能按命名猜。
- **勾选口径**：BACKLOG `[x]` 必须能被"限定条件"支撑（例：`module/ocr/**` 仍 exclude 时不能勾"58 对象可用"）。

## 输出格式

分两层：**回执给人看（聊天里）**、**详情落文件**。

### 回执（≤5 行，直接贴给用户）
```
1 结论：PASS / CHANGES(n)
2 八项核对：N/8 ✅，⚠ 的编号：…（无则写“全 ✅”）
3 最关键 1–2 条（每条一行，带证据要点）
4 non-blocking nit：k 条
5 证据：/tmp/outbox/<file>.md
```
### 详情（写 outbox，不贴进回执）
逐条：`①<判定> ⚠/✅：<命令与输出摘要/行号>` + **改法（哪个文件、改成什么）**。
CHANGES 不给改法等于没提。
