## 文件命名

`YYYYMMDD-HHMM-<类型>.md`，例如 `20261125-0852-main-ai.md`。
只保留当前这一棒；被接替的旧包**直接删除**（git 历史即复盘），不设 archive/。

**两类交接包，别混：**

| 类型 | 文件名 | 谁读 | 例子 |
|---|---|---|---|
| 主 AI 交接包 | `YYYYMMDD-HHMM-main-ai.md` | 接任的调度会话（上下文压缩/换人时） | `20261125-0852-main-ai.md` |
| D 棒交接包 | `YYYYMMDD-HHMM-d-reviewer.md` | 接任的调研兼评审（D）会话（D 换棒时） | 当前无（D2 未换棒） |

主 AI 交接包多写三块：会话名册（chat_id 实查）、排除记录全文、待办优先级；
**不要把 PAT 等密钥写进任何包**。

两类都由 **主 AI** 撰写（D-026）。

> 2026-11-15 用户决定：**交接包只留最新一份**，被接替的旧包直接删除（历史见 `git log -- docs/handoff/`）。

## 七要素模板

```markdown
# 交接 · <项目> <一句话标题>

> 时间：<YYYY-MM-DD HH:MM> ｜ 项目：<oas/thermal/ocr…> ｜ 上一棒：<哪条对话>
> 用途：接棒会话的第一动作是读本文 + 执行文末「启动动作」，不要先自由探索。

## 1. 当前任务目标

<一句话：最终要交付什么。再加一句「做到什么算完」= 验收口径>

## 2. 已完成工作

- <改完并验证过的：路径 / commit / 实测数值>
- <没验证的不许写这里>

## 3. 当前断点

- <具体到文件·函数·命令：现在停在哪一步>
- <有没有半成品改动、要不要回滚>

## 4. 关键约束

- <不能改什么 / 必须兼容什么 / 用户特别强调过什么>

## 5. 排除记录（已试过、不要再试）

- <方案 A → 为什么失败：报错原文或关键数值>
- <方案 B → 为什么放弃>
- <别人的结论里被否掉的说法>

## 6. 当前故障

1. <报错原文 / 复现步骤 / 卡在哪个判断>
2. <依赖缺失：服务没起、包没装、端口没听>

## 7. 启动动作

```sh
<接手方第一条命令，必须现在就能跑通>
```
```

## 合格判据（只看两条）

1. **接手方能不能直接执行第 7 节，不需要回头问方向？**
2. **第 1 节验收口径里的那个值，现在就能观察到吗？**

两条都「是」才能发。**为了压短而删掉「排除记录」或「启动动作」是错的** —— 那两块正是省掉一次返工的东西。
