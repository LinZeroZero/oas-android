## 1. 正常用例：`kb run 5 5 5`（应 4/4）

```
KbRun（daemon 侧三段）
displayId=-1 a=5s b=5s c=5s
A start=1794670096973 end=1794670101982 dur=5009ms
B start=1794670101984 end=1794670106993 dur=5009ms
C start=1794670106995 end=1794670112004 dur=5009ms

判定：lines ≥ 段秒数*0.8 且 maxGap ≤ 5000ms
phase    sec  lines   need   maxGap  frames(first->last)  verdict
A          5      6      4     1001                  n/a  pass
B          5      5      4     1001                  n/a  pass
C          5      5      4     1001                  n/a  pass
TOTAL     15     16     12     1001                  n/a  pass
n/4 = 4/4（全过）
status=done
```

`final.txt.json` 摘要：`passCount=4,total=4,verdict="pass"`，`phases` 恒 4 项（A/B/C/TOTAL）。

- `frames` 全为 `-1` → 因为 `displayId=-1`（`cmdHeartbeat` 允许 -1，但此时拿不到帧号），**不能**用它判「画面在动」；要判渲染必须在真实虚拟屏 displayId 上跑。
- `maxGap≈1001ms` 与心跳间隔 1000ms 一致，说明三段内 daemon 侧调度没有空洞。

## 2. fail-closed 用例：`kb run 0 0 0`（应 0/4，不许空过）

```
A          0      1      1        0                  n/a  FAIL
B          0      0      1        0                  n/a  FAIL
C          0      0      1        0                  n/a  FAIL
TOTAL      0      1      1        0                  n/a  FAIL
n/4 = 0/4（有段未过）
```

对应的 fail-open 缺陷由 D 的 4-eyes 评审发现（0 秒段会被 `lines >= seconds*0.8` 放过、
`phases` 为空时 TOTAL 误判 pass），返工见 `0671407`；分母恒 4 见 `ab0173a`；
`need` 下限取 1（显示与判据一致）见 `992baa0`。
