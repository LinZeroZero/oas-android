# BG-21 C 段预实验（pilot）· 本机能不能观测到整机 suspend

> 时间：2026-11-15 00:49–00:57（设备本地时间）｜基线 `main = f3d970c`｜jar 28650 B
> 只回答方法学问题：**这台机器上到底能不能观测到整机进入 suspend**。本文件数据**不得**用于「BG-21 通过/不通过」结论。

## 0. 先说一个害人的环境坑（新发现，与 BG-21 无关但会卡住所有人）

`super_admin:shell` 的**默认 cwd 无效**（已被删除的目录）。`app_process` 在这种 cwd 下会在 JVM 启动期就 SIGSEGV：

```
__strncat_chk  <- System_specialProperties  <- System.initUnchangeableSystemProperties <- System.<clinit>
Fatal signal 11 (SIGSEGV), code 1 (SEGV_MAPERR), fault addr 0x0
```

根因：`System_specialProperties` 用 `getcwd()` 填 `user.dir`，cwd 无效时返回 NULL，随后 `__strncat_chk` 解引用空指针。
**所有 `app_process` 调用（含交接包 §7 里写的）都必须先 `cd` 到一个真实存在的目录**；本棒统一 `cd /data/local/tmp`。
另注：`env -i` 清空环境**不能**绕过，反而变成「rc=0 但完全空跑、不写任何副作用」——更难看。别用 `env -i`。

## P0 链路（不熄屏，3s）

```
$ cd /data/local/tmp && CLASSPATH=/data/local/tmp/kbdaemon.jar app_process ... --cmd 'kb run 0 0 3 -1 /data/local/tmp/kb/p0.txt' --wait 15000
{"ok":true,"a":0,"b":0,"c":3,"displayId":-1,"report":"/data/local/tmp/kb/p0.txt"}
rc=0
```
`p0.txt` 落盘：
```
A dur=0ms   B dur=0ms   C dur=3003ms
phase sec lines need maxGap  verdict
A  0  1  1  0  FAIL
B  0  1  1  0  FAIL
C  3  4  3  1000  pass
n/4 = 1/4（有段未过）
```
判定：**G3 绿**（报告直接落盘、`n/4` 分母确为 4）。A/B 秒数为 0 时恒判 FAIL，属报告判定逻辑的边界形态，不是链路故障；正式测用 `5 5 65` 即 4/4。

## P1 四探针（4/4 都有明确值）

| 探针 | 命令 | 实测 |
|---|---|---|
| suspend 计数 | `cat /sys/power/suspend_stats/success` | **1164**（fail=135） |
| 内核锁 | `cat /sys/power/wake_lock` | **空** |
| 电源态 | `cat /sys/power/state` | **`freeze mem`**（两种都支持） |
| 屏/持锁者 | `dumpsys power \| grep -E 'mWakefulness=\|displayId'` | `mWakefulness=Awake`、`mHoldingDisplaySuspendBlocker=true`、`SCREEN_BRIGHT_WAKE_LOCK 'WindowManager/displayId:0'` uid=1000 pid=2106（system_server） |

注：`displayId:19` 是本棒之前游戏在前台时的编号；现在前台是 Operit，编号变成 `:0`。**编号会跟当前前台画面走，脚本里不能写死 19**。

判定：**G1 绿**。

## P2 阴性对照（能不能让 success 真的 +1）

三条路径实测，前两条**无效**，第三条**有效**：

1. `dumpsys deviceidle force-idle`（doze 未启用）→ `Unable to go deep idle; not enabled`，delta=0。**对照没生效，不算证据**。
2. `dumpsys deviceidle enable all` + `force-idle` → 真的进了 `mState=IDLE`，但**亮屏**下 5s delta=0。亮屏本就不可能 suspend，此条**无解释力**。
3. 灭屏 20s（`input keyevent 26`，`mWakefulness=Dozing`、内核 `wake_lock` 空）逐点采样：
   ```
   t=0  success=1164 fail=135
   t=5  success=1164 fail=135
   t=12 success=1164 fail=135
   t=20 success=1164 fail=135
   ```
   **success 与 fail 都不动** → 内核这 20 秒压根没尝试过 suspend（fail 不动 = 连失败都没有）。`last_failed_dev=alarmtimer.0.auto` 是历史值。
   也就是说：**正常灭屏待机状态下，这台机器不产生 suspend 事件**，靠「灭屏 60s 前后 success 差值」当判据在本机行不通。
4. 决定性安全试探：`echo freeze > /sys/power/state`（s2idle，定时器即回，预置 `rtc0/wakealarm=+8s` 兜底）：
   ```
   b0=1164  freeze_rc=0  b1=1165  delta=1  fail=135  mWakefulness=Awake
   ```
   **success 1164→1165，delta=1，机器自动回到 Awake。**
   结论：① 这台机器的 suspend **是可观测的、计数会正常 +1**；② 但**只有在被显式踢进 suspend 时才会**（`echo freeze|mem`），屏灭待机路径不会自己进去。

判定：**G2 绿**（存在一条路能让计数 ≥ +1，且零风险）。

## P3 对照灵敏度（灭屏各 15s，`--wakelock on` vs `off`）

| 组 | C 段 | lines | maxGap | verdict |
|---|---|---|---|---|
| `--wakelock on` | 15016ms | 15 | **1001ms** | pass |
| `--wakelock off` | 15023ms | 16 | **1003ms** | pass |

差值 2ms，落在 tick 抖动内 → **`--wakelock on/off` 这组对照在本机没有灵敏度**。
原因与 P2 一致：灭屏待机本来就不进 suspend，持不持 PARTIAL 锁都一样；该对照的设计前提（「屏灭就会 suspend，锁能挡住」）在本机不成立。

## P4 时长标定（灭屏 10s / 30s）

| 时长 | C 段 | lines | maxGap |
|---|---|---|---|
| 10s | 10028ms | 10 | **1001ms** |
| 30s | 30047ms | 30 | **1001ms** |

抖动 ≤3ms，1Hz 心跳在这个平台上非常稳。标定结论：
- 建议正式测时长：**65s 够用**（30s 已稳定，无需更长）；60s 亦可。
- `maxGap` 阈值：基线 ≤1003ms，建议 **1500ms**（约 1.5 个 tick，抗一次抖动），保守可放 2000ms；现报告默认 5000ms 对 C 段偏松。

## 正式测（E 段，单组）

因 P3 已证 on/off 无灵敏度，按 §7.4 括号条款**只做一组**（`--wakelock on`，真熄屏 65s）：

```
before=1165
A dur=5006ms  B dur=5007ms  C dur=65107ms
phase sec lines need maxGap  verdict
A   5   6   4   1000  pass
B   5   5   4   1001  pass
C  65  65  52   1003  pass
TOTAL 75 76 60  1003  pass
n/4 = 4/4（全过）   status=done
after=1165 delta=0
```

**真熄屏 65 秒、daemon 心跳一拍不漏（65/65，maxGap 1003ms）**；同期整机 suspend 计数 delta=0（与 P2 一致，属预期）。

## Gate 结论

| Gate | 判定 | 依据 |
|---|---|---|
| G1 四探针都有明确值 | **绿** | P1 表 |
| G2 至少一条路让 success ≥ +1 | **绿** | `echo freeze` → 1164→1165 |
| G3 `kb run` 可直接跑且报告落盘、分母为 4 | **绿** | P0 `n/4=1/4`，正式测 4/4 |

## 一句话：本机能测到什么 / 测不到什么

**能测到**：daemon 侧三段计时与 1Hz 心跳在真熄屏下是否连续（`kb run` 报告落盘、`maxGap` 稳定在 ≤1003ms）——这是本棒真正想要的那个量。
**测不到**：用「灭屏 N 秒前后 `suspend_stats/success` 差值」证明整机进过 suspend。本机屏灭待机路径**从不自己进 suspend**（20s 内 success/fail 全不动），只有 `echo freeze|mem` 显式踢才 +1、且 s2idle 秒回。因此 `--wakelock on/off` 对照组无灵敏度，不能作为 BG-21 的判据。
