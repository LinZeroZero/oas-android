# BG-29 前置探针：uid 0 daemon 到底落在哪个 cgroup（只读）

> 时间：2026-11-15 14:45–14:55（设备时钟 CST）｜分支 `feat/bg22-setSurface` @ `f03e928`（源码止于 `656ec1a`，其后仅 docs 提交）
> 结论：**本机 uid 0 daemon 六行 cgroup 全在 `/`，不在 `/apps/`；BG-29「学 Shizuku 切 cgroup」在本机无收益。** 真正该改的是启动自检的判据行。
> 数据来源：§2 的 ①–④ 由 B（只读诊断位）执行；⑤–⑥（含短命 daemon 实例）由主 AI 执行并复核。原始回执各自留存于会话。

## 1. 为什么先测

`docs/BACKLOG.md` BG-29 的前提是「uid 0 daemon 落在 `/apps/` cgroup，需 `setsid` + 切 cgroup + 切 mnt ns」。但 `poc/displayserver/src/org/onmyoji/oas/server/Main.java:102-107` 已有启动自检（`checkEnv`，`:149-194`），其第③条会在「memory cgroup 含 `/apps/`」时 `exit 3` 拒绝启动；而历次实验的 daemon 都起得来。两者矛盾 → 先测事实，再决定要不要写代码。

## 2. 方法（只读；仅一条短命实例，不建屏）

- ① `su -c 'id; cat /proc/self/cgroup; cat /proc/self/oom_score_adj'`
- ② `cat /proc/1/cgroup`
- ③ `mount | grep -i cgroup`；`grep -i cgroup /proc/self/mountinfo`
- ④ `ls /sys/fs/cgroup`；`cat /sys/fs/cgroup/cgroup.controllers`；`ls -ld /dev/cg2_bpf`
- ⑤ 对照组：本机 app 进程 `pid 5207`（`com.ai.assistance.operit`，uid 10252）的 `/proc/5207/cgroup`
- ⑥ 短命 daemon 实例：`CLASSPATH=/data/local/tmp/kbprobe.jar app_process /system/bin org.onmyoji.oas.server.Main --socket oas.probe`（**不 `create` 任何屏**），读 `/proc/<pid>/cgroup`、`oom_score_adj`、ppid，随后 `kill` + `rm` 清理

## 3. 原始数据

| 对象 | cgroup 全行 | oom_score_adj |
|---|---|---|
| `su`（`context=u:r:magisk:s0`） | `5:freezer:/` `4:memory:/` `3:cpuset:/` `2:cpu:/` `1:blkio:/` `0::/` | -1000 |
| `init`（pid 1） | 同上，六行全 `/` | — |
| app `pid 5207`（Operit，uid 10252） | `5:freezer:/` `4:memory:/apps/uid_10252` `3:cpuset:/top-app/other` `2:cpu:/top-app` `1:blkio:/` `0::/uid_10252/pid_5207` | 0 |
| **daemon `pid 15279`** | `5:freezer:/` `4:memory:/` `3:cpuset:/` `2:cpu:/` `1:blkio:/` `0::/` | **-1000** |

daemon 侧补充：ppid cmdline = `/system/bin/sh`（root shell）；启动首行 = `READY oas.probe (abstract)`（即 `checkEnv` 通过）；`kill` 后 `ps -A | grep oas.probe` 计数 = **0**，`kbprobe.jar` / `probe.out` 均已删除（`No such file`）。

挂载与目录（决定「能切到哪儿」）：

- v1 控制点：`/dev/blkio`、`/dev/cpuctl`、`/dev/cpuset`、`/dev/memcg`、`/dev/freezer`（`mountinfo` 条目 145/149/151/153/136）
- v2：`/sys/fs/cgroup`（`cgroup2`，`mountinfo` 147），根下 **312 个 `uid_*` 目录、无 `apps/`**；`cgroup.controllers` = **空**
- `/dev/cg2_bpf`：**不存在**（`ls` exit 1）
- app 的 v2 目录内确有 `cgroup.freeze`（`/sys/fs/cgroup/uid_10252/pid_5207/`）

## 4. 判读（三条，全部有原始值支撑）

1. **v1 的 `freezer:` 行零区分度**：app 与 daemon 都显示 `/`。所以「cgroup 不在 `/apps/`」这条验收，只看 `freezer:` 行会**永远通过**、只看 `memory:` 行只能证明 memory 归属——两者都不足以判断「会不会被冻」。
2. **真正决定能不能被冻的是 v2 行**：app = `0::/uid_10252/pid_5207`（per-process 组，AOSP 冻结经 `SetProcessProfiles(uid,pid,{"Frozen"})` 落到该目录的 `cgroup.freeze`）；daemon = `0::/`（root，不在任何 per-process 组）。→ **cached-app freezer 结构上够不到这个 daemon**，与「它没有 `ProcessRecord`」互为印证。
3. **BG-29 判为「无需实现」**：uid 0 由 root shell 起时全控制器继承 `/`；本机既无 `/dev/cg2_bpf`、`cgroup.controllers` 也为空，Shizuku 式 `switch_cgroup`（`/acct` → `/dev/cg2_bpf` → `/sys/fs/cgroup`）在本机是 **no-op**。值得抄的只剩「`setsid` + 父进程退出 + 独立进程名」，那三条与 BG-29 的原始动机（脱离 `/apps/`）无关，属独立小改进。

## 5. 附带发现：现有自检有盲区

`Main.java` 的 `checkEnv` 只读 `:memory:` 那一行（`memoryCgroupOf()`）。若 daemon 哪天被 app 域进程 fork 出来、而 memory 恰为 `/`、v2 行却在 `/uid_x/pid_y`，**自检会放行**，随后静默被冻——正是自检要防的那种失败。修法（记 `BACKLOG.md` BG-30）：主判据改成「`0::` 行必须是 `/`」，memory 行降为附带记录。

## 7. 复现命令

```sh
# root shell；起实例前必须 cd 到真实存在的目录（工作区原路径；默认 cwd 无效会让 app_process 启动期 SIGSEGV）
cd /data/local/tmp
cp <WS>/app/src/main/assets/server/server.jar kbprobe.jar
(CLASSPATH=/data/local/tmp/kbprobe.jar /system/bin/app_process /system/bin \
  org.onmyoji.oas.server.Main --socket oas.probe >/data/local/tmp/probe.out 2>&1 &)
sleep 3; ps -A -o PID,PPID,ARGS | grep 'oas.probe' | grep -v grep
# 用上一步的 pid：
cat /proc/<pid>/cgroup; cat /proc/<pid>/oom_score_adj
kill <pid>; rm -f /data/local/tmp/kbprobe.jar /data/local/tmp/probe.out
```
